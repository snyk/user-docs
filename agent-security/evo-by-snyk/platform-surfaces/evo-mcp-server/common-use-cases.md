# Common Use Cases

{% hint style="info" %}
You configure any non-Snyk MCP server mentioned in this article in your own client. Snyk does not provide or support those servers, and the steps that use them depend on the permissions you grant.
{% endhint %}

The Evo MCP server runs in the same agent session as other connected MCP servers. With the right integration, you can turn an answer from Evo into a dashboard, a ticket, or a policy.

## Visualizing the estate

{% hint style="info" %}
Requires Evo MCP server and a client that can build dashboards, artifacts, or documents.
{% endhint %}

Use case to produce a reporting pack for the estate.

Steps:

1. How many AI assets do we have, broken down by type and by source? Establishes scope: models, agents, MCP servers, skills, repositories, and machines.
2. Group our models by vendor and by country of origin.
3. Break our models down by license type.
4. List all open violations grouped by policy and severity.
5. Build me a dashboard from this, with a chart for each section.

Outcome: a dashboard built from live tenant data, regenerated on demand.

## Turning a violation into a ticket

{% hint style="info" %}
Requires Evo MCP server and a ticketing MCP server such as Jira connected in the same client.
{% endhint %}

Use case for creating tickets for policy violations.

Requires: Evo MCP server and a ticketing MCP server such as Jira connected in the same client.

Steps:

1. Show me the open violations for this policy, with the affected asset and where it was found.
2. Group them by repository so we raise one ticket per team rather than one per violation.
3. Create a Jira ticket for each group in this project, with the asset list and the remediation notes in the description.
4. Give me the ticket details so I can reference them.

Outcome: tickets in your own tracker, populated from live violation data.

## Creating a policy from estate data

{% hint style="info" %}
Requires Evo MCP server with write permissions.
{% endhint %}

Use case to create a policy based on risks in your estate.

Steps:

1. How many skills in our estate score 500 or above for insecure credential handling?
2. Show me those skills ordered by that score, with the machines they are on.
3. Create a policy that assigns High severity to skills scoring 500 or above for insecure credential handling.
4. Show me the violations generated by this policy.

Outcome: a policy tuned against the estate it governs.
